# HD 派生收款地址（仅 EVM）

开启后，指定的 EVM 交易类型在下单时不再从地址池里选地址，而是为每个订单从助记词派生一个新地址。订单金额不再递增，也不需要独占锁定。

## 环境变量

| 变量 | 说明 |
| --- | --- |
| `HD_MNEMONIC` | BIP39 英文助记词，不支持 passphrase。服务启动读取后立即从进程环境中移除，不写入数据库、日志或后台配置。 |
| `HD_TRADE_TYPES` | 逗号分隔的交易类型，例如 `usdt.bep20,usdt.erc20`；`evm` 表示所有 EVM 类型。留空表示不启用。 |

可写入 `.env`，也可通过进程环境传入。

启动校验规则如下，校验不通过时服务启动失败：

- 配置了 `HD_TRADE_TYPES` 但没有 `HD_MNEMONIC`：启动失败。
- `HD_MNEMONIC` 格式或校验和不合法：启动失败。
- `HD_TRADE_TYPES` 含未知或非 EVM 类型（如 Tron、Solana、Aptos、Ton）：启动失败。
- 两个变量都为空：功能关闭，行为与原来一致。
- 只配置助记词、`HD_TRADE_TYPES` 为空：允许，不启用任何类型。

## 行为

- 派生路径固定为 `m/44'/60'/0'/0/n`，`n` 取 `bep_derived_address` 表的自增 ID，记录在 `derive_index` 列。
- 请求中指定了 `address` 时仍使用指定地址，不派生。
- 收银台重选支付方式时，如果原地址是当前助记词派生的，则继续使用该地址；原订单没有地址或用的是地址池地址时才派生新地址。
- 未列入 `HD_TRADE_TYPES` 的类型仍走原来的地址池逻辑。

## 灰度

先只配置一个类型（例如 `usdt.bep20`），确认收款正常后再逐步加入其它类型，最后可改为 `evm`。移除某个类型后，新订单回到地址池，已派生的地址仍保留在表中。

## 资金归集（仅 usdt.bep20）

订单在链上确认成功后，程序会自动把该订单派生地址里的全部 USDT 转到归集目标地址。目前只支持 BSC 上的 `usdt.bep20`，其它 EVM 类型不会入队。

### 默认行为

- 归集目标默认是同一套助记词的 `m/44'/60'/0'/0/0`，也就是 MetaMask / Trust Wallet 里的第一个账户。设置了 `HD_COLLECT_ADDRESS` 则转到该地址。
- 派生地址收到 USDT 后没有 BNB，转出需要手续费。程序会先从 `m/44'/60'/0'/0/0`（手续费地址）给派生地址转一小笔 BNB，等链上确认后再转 USDT，数量是该地址当时的全部 USDT 余额。转完后把剩余的 BNB 转回归集目标。
- **手续费地址里必须预留 BNB。** 手续费地址不足时，日志会打印「主地址 BNB 不足，请先向主地址 xxx 打入一些 BNB 作手续费」，记录保持待处理并每 5 分钟重试，充值后会自动继续，不会丢单。
- 私钥只在签名时由助记词在内存里派生，用完立即清零，不写入磁盘、数据库或日志。

### 环境变量

| 变量 | 说明 |
| --- | --- |
| `HD_SWEEP_ENABLED` | `true` / `false`。留空时：已配置 `HD_MNEMONIC` 且 `HD_TRADE_TYPES` 包含 `usdt.bep20` 则自动开启。显式写 `true` 但 HD 派生未启用，服务启动失败。 |
| `HD_COLLECT_ADDRESS` | 可选。归集目标地址，必须是合法的 EVM 地址，否则启动失败。留空则用 index 0。 |
| `HD_SWEEP_GAS_BNB` | 可选。单次给派生地址补充手续费的 BNB 上限，写十进制数，如 `0.001`。所需手续费超过它时记录会标记为失败，不会发交易。留空不限制。 |

RPC 使用后台「区块节点」里配置的 BSC 节点，需要节点可用且支持发送交易。

### 触发、状态与重试

- 触发：订单经过链上确认（`markFinalConfirmed`）后入队，每个订单只入队一次（以 `trade_id` 去重）。后台人工「补单」不会触发归集，也不会为历史订单回填。
- 后台任务每 15 秒处理一批记录，一轮最多 20 条，按顺序串行执行，避免手续费地址同时发多笔交易导致 nonce 冲突。
- 状态：`pending`（待处理）→ `funding`（已发手续费，等确认）→ `funded`（手续费已到账）→ `sweeping`（已发 USDT 转账，等确认）→ `swept`（USDT 已转出）→ `done`（完成）。另有 `skipped`（该地址 USDT 余额为 0）和 `failed`（需要人工处理）。
- 幂等：每一步都先读链上状态再决定动作，发 USDT 时取的是当前全部余额。已经转走的钱不会再转第二次，手续费已够时也不会重复补给。广播报错时保留已记录的交易哈希，等回执，超过 10 分钟没有回执才回退重来。
- 自动重试：失败后按 2、4、8……分钟退避（最长 60 分钟），累计超过 8 次标记为 `failed`，不再自动重试。
- 手动处理：后台「归集记录」页面可以查看每条记录的状态、交易哈希和最后错误，`failed` 的记录有「重试」按钮，也可以按派生地址记录 ID 手动入队归集。

### 手续费地址要预留多少 BNB

按代码里的估算：ERC20 转账 gas 取节点估算值（失败用 100000 兜底）再乘 1.3，补给量再乘 1.2，另加补给交易和回收交易各 21000 gas。BSC 的 gasPrice 通常是 1 gwei 到几 gwei，所以每个订单大约消耗几万到十几万 gwei，也就是 0.0001 到 0.0005 BNB 量级，其中未用完的部分会随归集转回目标地址。

这是估算，不是保证。建议手续费地址一开始预留 0.01 BNB 以上，之后按订单量观察并补充。gasPrice 飙高时单笔消耗会明显增加。

### 查看归集状态

- 后台菜单「归集记录」：列表、状态、交易哈希、错误信息，页面顶部显示归集目标地址和手续费地址。
- 日志里搜索「HD 归集」。

### 自己要做的事

- 备份助记词。归集目标和手续费地址都来自同一套助记词，丢了助记词，资金和手续费都取不回。
- 手续费地址有 BNB，且 BSC 节点可用，否则订单收款不受影响，但归集会一直等待。
- 更换助记词后，旧助记词派生的地址不会被新助记词归集。

## 注意事项

- 助记词必须离线备份，丢失后派生地址上的资产无法取回。
- 更换助记词后会产生新的 `key_fingerprint`，旧记录只能用旧助记词归集，旧助记词不能丢弃。
- `key_fingerprint` 是 index 0 地址的 SHA256 前 16 位，只用于区分记录，不能还原助记词。
